# SupportPulse AI

AI-ассистент клиентской поддержки для e-commerce: классифицирует обращения, сам ходит в МойСклад и СДЭК,
закрывает рутину автоматически (deflection) и готовит черновики + быстрые действия для оператора.

## Запуск

```bash
npm install && npm run dev
```

Откройте http://localhost:3000. Работает сразу на mock-данных — ключи не нужны.

- `/login` — вход для операторов (демо: любой e-mail и пароль от 6 символов, без реальной авторизации)
- `/live` — экран для проектора на питче: большой QR-код на чат, живая лента сообщений жюри с ответами AI и временем ответа, счётчик «AI сэкономил за питч N ₸», кнопки «Автодемо» (запасной сценарий, если жюри молчит) и «Сбросить демо»
- `/chat` — чат клиента, как виджет на сайте магазина: текст, голосовые (расшифровка Groq Whisper, нужен https или localhost), фото товара (Gemini описывает, видит ли брак), оценка ответа 👍/👎 (CSAT на дашборде) (удобно открыть с телефона в той же Wi-Fi сети: `http://<IP-компьютера>:3000/chat`)
- `/` — панель оператора: очередь обновляется раз в 3 сек, срочные (негатив или высокая срочность) — сверху с меткой «Срочно»; демо-сценарии A–D создаются один раз за запуск сервера
- `/analytics` — дашборд: сэкономленные $/часы, Deflection Rate, тикеты, SLA по приоритетам, настроение клиентов, темы, AHT. Кнопка «Сводка для руководителя от AI»: LLM по метрикам и живым обращениям пишет главное, выводы и действия на завтра (каждое число проверяется по данным, иначе — шаблонная сводка). Калькулятор ROI в ₸ на ваших цифрах. Обращения, которые обработал агент, появляются на дашборде вживую (столбец «Live» и метка LIVE в таблице, обновление раз в 10 сек); остальное — демо-история. Живые тикеты хранятся в памяти сервера и сбрасываются при перезапуске
- `npm test` — самопроверка демо-сценариев движка

## API

```
POST /api/agent      { order_id?, phone?, message }  → intent, urgency, confidence, mode (auto|draft), reply, order, shipment, kb, actions
POST /api/actions    { action, order_id, track }      → extend_storage | create_return_waybill | create_return_request
GET  /api/analytics?period=week|month|quarter
```

Ответ отправляется автоматически, только если confidence > 90% и ситуация рутинная (статус заказа без задержки).
Возвраты, брак и задержки всегда уходят оператору на проверку.

## Демо на питче: QR-код для жюри

Чтобы жюри писало с телефонов (в т.ч. с мобильного интернета), сайт открывается в интернет через бесплатный туннель Cloudflare:

1. Один раз установите cloudflared: `winget install Cloudflare.cloudflared`
2. В одном терминале: `npm run build && npm start` (продакшен-режим: быстрее, без значка dev-сервера). Для разработки — `npm run dev`.
3. Во втором терминале: `npm run tunnel` — в выводе появится адрес `https://….trycloudflare.com`.
4. Откройте на проекторе `https://….trycloudflare.com/live` — QR-код сам возьмёт этот адрес.

Адрес туннеля меняется при каждом запуске — открывайте `/live` по новому адресу (или нажмите «Изменить адрес для QR»). Туннель открывает в интернет всё приложение, включая панель оператора (вход демонстрационный), поэтому не оставляйте его запущенным после питча. Чат ограничен 8 сообщениями в минуту с одного IP, чтобы не сжечь квоту LLM.

Тикеты сохраняются в `data/tickets.json` и переживают перезапуск сервера — перед показом нажмите «Сбросить демо» на `/live`.

Если после добавления новых файлов в dev-режиме не применяются стили — остановите сервер и удалите папку `.next/dev` (кэш Turbopack).

## Как работает агент

1. Ищет заказ: номер из поля или текста (в т.ч. «Тапсырыс 48201»), иначе по телефону → МойСклад → СДЭК.
2. Один запрос к LLM: интент, настроение, статьи базы знаний и **текст ответа** — на языке клиента (русский/казахский), с тоном под настроение (недовольному — извинение).
3. Ответ LLM принимается, только если каждое число в нём (номер заказа, трек, сумма) есть в данных заказа, базе знаний или сообщении клиента. Иначе — проверенный шаблон.
4. Агент сам выполняет безопасные действия: при задержке доставки заранее продлевает хранение в ПВЗ (один раз на посылку) и сообщает клиенту новую дату — в панели и на `/live` видно «AI выполнил: …».
5. Негатив поднимает срочность на ступень (строже SLA, выше в очереди). Рутина с уверенностью > 90% отвечается сразу, остальное — черновик оператору, а клиенту в чате/Telegram — «передал оператору, ответит в течение N».

LLM идёт по цепочке моделей: **Groq** `qwen/qwen3.8-27b` → `openai/gpt-oss-120b` → **Gemini** `gemini-3.5-flash` → `-flash-lite` → `3.1-flash-lite`. У каждой модели своя бесплатная квота; модель, упёршаяся в лимит или не ответившая за 8 сек, пропускается до сброса. Если недоступны все — работают правила и шаблоны, демо не ломается. Groq отвечает за 0,5–1 сек.

## Telegram-бот

1. В Telegram откройте @BotFather → `/newbot` → получите токен.
2. Вставьте его в `.env.local`: `TELEGRAM_BOT_TOKEN=...` и перезапустите `npm run dev`.
3. Напишите боту — обращение появится в панели оператора с меткой Telegram, ответ оператора придёт в Telegram.

Бот работает через long polling внутри сервера Next — подходит для локального запуска и VPS. На serverless (Vercel) нужен webhook.

## Подключение реальных API

Скопируйте `.env.example` в `.env.local` и заполните ключи — сервисы сами переключатся с mock на реальные API:

| Переменная | Что включает |
|---|---|
| `GROQ_API_KEY` | Основной LLM: разбор обращения, настроение, выбор статей базы знаний и текст ответа одним вызовом |
| `GEMINI_API_KEY` | Запасной LLM, если квота Groq исчерпана |
| `MOYSKLAD_TOKEN` | `src/lib/services/moyskladService.ts` → МойСклад JSON API 1.2 |
| `CDEK_CLIENT_ID`, `CDEK_CLIENT_SECRET` | `src/lib/services/cdekService.ts` → СДЭК API v2 (OAuth) |
| `TELEGRAM_BOT_TOKEN` | Telegram-бот как второй канал обращений |
| `PUBLIC_URL` | Постоянный публичный адрес для QR-кода (если есть свой домен/деплой) |

Трек СДЭК в МойСкладе читается из доп. поля «Трек СДЭК» — переименуйте под свою учётку.
Быстрые действия (продление хранения, накладная, заявка на возврат) пока mock в обоих режимах.

## Структура

```
src/
  app/
    globals.css              дизайн-токены: цвета бренда и графиков, шрифты, фокус
    login/page.tsx           вход
    (app)/layout.tsx         шапка приложения
    (app)/page.tsx           панель оператора
    (app)/analytics/page.tsx дашборд
    api/agent|actions|analytics/route.ts
  components/                Nav, ThemeToggle
  lib/
    agent.ts                 классификация, поиск по базе знаний, ответ/черновик
    agent.check.ts           самопроверка сценариев (npm test)
    ticketStore.ts           тикеты с перепиской (сохраняются в data/tickets.json)
    vision.ts                фото от клиента → описание и есть ли брак (Gemini)
    rateLimit.ts             лимит сообщений с одного IP
    summary.ts               сводка для руководителя (LLM + проверка цифр + шаблон)
    inbox.ts                 входящие из всех каналов → агент → тикет; ответы оператора → клиенту
    telegram.ts              Telegram Bot API (long polling)
    roi.ts                   формула ROI-калькулятора
    mockData.ts              заказы, отправления, база знаний, сценарии, аналитика
    services/moyskladService.ts, cdekService.ts
```

Дизайн: синий «trust blue» `#2563EB`, шрифты Manrope (заголовки) + Inter (текст) с кириллицей, светлая/тёмная тема по системной настройке.

Стек: Next.js 16 (App Router), TypeScript, Tailwind CSS 4, Lucide, Groq + Gemini API (REST).
